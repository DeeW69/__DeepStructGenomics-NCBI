# v0.5.0-rc1 — préparation, non publiée

Version du paquet : `0.5.0rc1`. Dernière release stable : v0.4.6.
Cette passe prépare la première candidate desktop ; elle ne publie pas de stable.

## Contenu

- Parcours NCBI, FASTA et saisie directe, worker annulable et réouverture.
- Structure secondaire centrale, inspecteur WT/MUT et états visuels communs.
- Alignement global affine borné : substitutions, indels, sélection des homologues,
  deltas sans gaps et comparaison des paires dans le repère de l'alignement.
- Hi-C, rapports et exports du moteur existant.
- Configuration unique `.env`/environnement/CLI/GUI, profils avancés et tableau
  virtualisé ; configuration effective conservée dans chaque analyse.
- Alignement seul et benchmark synthétique reproductible, sans repliement ARN.
  [Configuration](../configuration.md) · [Mesures Windows](../benchmarks/alignment_windows.md).

## Validation de la candidate

Recette locale du 8 octobre 2026 : **285 tests réussis** (Windows, Python 3.11.9,
dépendances verrouillées, options research et GUI). Wheel et sdist construits ;
wheel importé et exercé hors du dépôt : CLI, configuration externe, export,
réouverture et GUI. Aucun `.env` ni `.env.example` présent dans les deux archives.
Dix benchmarks manuels d'alignement de 1 M à 50 M sont publiés séparément ; aucune
mesure de performance Linux n'est revendiquée.

Les tests automatisés couvrent notamment les mappings réciproques, répétitions,
indels terminaux/internes, changements de partenaire, paires touchées par un gap,
exports/réouverture, anciens résultats positionnels, limite de taille, sélection
2D dans les deux sens, couleurs VTK et le parcours NCBI mis en cache jusqu'au worker.
Les tests desktop couvrent aussi la référence seule, les entrées FASTA/directes,
Hi-C, annulation, erreurs, fermeture et réouverture.

La recette visuelle Windows utilise la démo `GGGGAAAACCCC / GGGGUAAAACCCA`, en
fenêtre 1100×760, fenêtre standard et plein écran. La vue native VTK est chargée
à part ; les jobs CI Linux/Windows exécutent Qt hors écran, sans valider le rendu
OpenGL de chaque carte graphique. Les captures README proviennent du logiciel.

Avant une stable, faire effectuer la recette par un nouvel utilisateur sur les
postes cibles : NCBI → choix WT → mutant → comparaison → export → réouverture,
puis le parcours Hi-C. Les contrôles automatiques ne remplacent pas cette recette.

## Migration et limites

Lire [alignment.md](../alignment.md) avant d'exploiter les nouveaux CSV/JSON :
quand l'alignement est actif, les positions des changements et hotspots sont des
colonnes d'alignement ; les positions WT/MUT restent disponibles séparément.
Les coordonnées natives des paires et structures ne changent pas.

Les fichiers historiques sans alignement restent positionnels et ne sont pas
réécrits. Les très anciens manifests sans structures secondaires nécessitent
toujours une régénération, comme avant cette candidate.

Limites : scoring conventionnel et optima parfois ambigus ; défauts à 4 millions
de cellules et 10 000 bases par séquence, configurables. Repliement Nussinov potentiellement
coûteux, aucune interprétation clinique. La 3D reste schématique ; les connecteurs
WT/MUT du viewer CLI sont refusés avec alignement. Aucun installateur autonome
n'est fourni dans cette passe.
