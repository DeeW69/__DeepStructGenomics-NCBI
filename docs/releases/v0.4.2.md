# v0.4.2 — FASTA par lots

```bash
python scripts/run_pipeline.py --batch-fasta data/examples/batch.fasta --output-dir outputs_batch
```

Le dossier de sortie doit être nouveau. Chaque entrée reçoit un dossier numéroté,
ses rapports JSON/Markdown/CSV et ses artefacts de visualisation. Les identifiants
dupliqués sont conservés et ne provoquent aucun écrasement. La provenance contient
le chemin FASTA et le numéro d'entrée depuis 1.

Une entrée invalide produit `error.json` et le lot continue. `batch_summary.json`
répertorie réussites, erreurs et chemins relatifs des rapports. La CLI retourne 2
si au moins une entrée échoue, 0 sinon. Une erreur d'accès disque interrompt le lot.
Une erreur de cadrage FASTA (données avant le premier en-tête, fichier vide) est fatale.
Le mode lot ne compare pas de mutants ; il conserve les seuils du pipeline.

Traitement séquentiel ; chaque repliement conserve le coût cubique du modèle ARN.
Les entrées sont actuellement conservées en mémoire. Tests de collisions,
provenance, entrées invalides et statut CLI dans `tests/test_batch.py`.
