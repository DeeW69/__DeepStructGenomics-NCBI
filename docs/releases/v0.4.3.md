# v0.4.3 — Évaluation ARN

```bash
python scripts/evaluate_rna.py --reference data/examples/rna_reference.json --output outputs_evaluation/metrics.json
```

Le JSON d'entrée contient `source` (provenance) et `records`, une liste d'objets
`id`, `sequence`, `reference` (dot-bracket `.()`). Les identifiants sont uniques.
Trois méthodes sont comparées : modèle Nussinov pondéré du projet, appariement
glouton gauche/droite et témoin sans paires. Les résultats détaillent TP/FP/FN,
précision, rappel, F1 par entrée et agrégats micro (sommes des comptes).
Les rapports de division indéfinis valent `null`, y compris pour deux ensembles
vides. Les paires doivent correspondre exactement ; aucun appariement tolérant
les décalages ni pseudonœud n'est pris en charge.

Pour comparer des méthodes externes, ajouter à chaque entrée
`"predictions": {"RNAfold-version-parametres": "...((...))..."}` avec une
structure de même longueur que la séquence. Chaque méthode doit couvrir toutes
les entrées. Le champ global `method_provenance` peut décrire versions, paramètres
et origine des sorties. Voir la [documentation RNAfold](https://www.tbi.univie.ac.at/RNA/RNAfold.1.html)
pour produire ces prédictions ; RNAfold n'est pas installé ni exécuté par cet outil.

Le rapport conserve SHA-256 du jeu, provenance, paramètres ARN et date UTC.
Le jeu fourni est **synthétique**, rédigé pour vérifier les métriques et les chemins
de calcul. Ses scores ne mesurent pas la validité biologique et ne démontrent pas
une supériorité du modèle. L'évaluation sur un corpus expérimental indépendant
reste à réaliser avec des références et conditions comparables.

Tests : métriques connues, structures malformées, méthodes externes, identifiants
dupliqués et couverture incomplète. Aucune nouvelle dépendance.
